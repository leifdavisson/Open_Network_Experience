NAV SELECTOR: #nav-monitor-reports / #nav-monitor-noc

PRIORITY: 🔴 HIGH

USER IMPACT:
  1. The Reports & Forensics Incident Evidence Vault table fails to populate newly captured PCAP evidence during standard background dashboard polling. Every 10 seconds, `main.js:loadDashboardData()` attempts to fetch `/api/v1/evidence` without an `X-API-Key` header, returning `HTTP 401 Unauthorized`. This spams browser error logs and leaves the Evidence Vault empty.
  2. In `server/static/js/modules/api.js`, escaped template literal backticks (`\`HTTP Error: \${response.status}\``) and a syntax/contract discrepancy between `fetch()` Response objects and `apiClient()` parsed JSON data introduce fragile exception handling across frontend callers expecting standard `.ok` or `.json()` APIs.
  3. When viewing Slide 5 (NOC Wallboard Grafana Multi-Dashboard Embed), embedded dashboard iframes load from port 3000 without credentials or fallback handling when Grafana session cookies are uninitialized.

---

## SUMMARY
During automated UAT verification of the Reports & Forensics view (`#view-monitor-reports`), PCAP capture snapshots triggered against online edge sensors generated valid archive bundles on the backend (`HTTP 200 OK`). However, the Evidence Vault UI table remained in an empty state (`"No incident forensic archives captured recently."`). Investigation revealed that the periodic dashboard refresh loop in `main.js` executes unauthenticated GET requests to `/api/v1/evidence`. Because `/api/v1/evidence` was hardened in `server/routers/telemetry.py` to enforce `verify_admin_key`, all unauthenticated requests return `401 Unauthorized` (`{"detail":"Invalid or missing admin API key"}`). Supplying `X-API-Key: admin-noc-key-change-me` immediately returns HTTP 200 OK with the full evidence archive array.

## EXPECTED RESULT
1. The background polling loop in `loadDashboardData()` must include the required `X-API-Key: ADMIN_KEY` header when querying `/api/v1/evidence`, matching other admin endpoints (`/api/v1/sensors`, `/api/v1/probes`, `/api/v1/schedules`).
2. The Evidence Vault table should automatically refresh and display active forensic PCAP captures.
3. Centralized `apiClient()` helper should be syntactically valid and consistently utilized across all modules without syntax errors or contract mismatches.

## ACTUAL RESULT
1. `GET /api/v1/evidence` receives `401 Unauthorized` every 10 seconds.
2. Evidence table remains empty despite existing captured bundles in SQLite.
3. Developers and operators cannot review packet captures from the web UI without manual API requests.

## RECOMMENDATION & FIX
1. **Pass `X-API-Key`**: Ensure all calls to `/api/v1/evidence` include `{ headers: { 'X-API-Key': ADMIN_KEY } }` or use an `apiClient()` that handles authentication injection transparently.
2. **Align API Response Contract**: Ensure callers handle either the direct parsed JSON returned by `apiClient` or retain the native `Response` semantics (`if (res.ok)` / `await res.json()`).
3. **Clean Syntax**: Ensure `api.js` contains valid unescaped template literals without rogue backslashes.
