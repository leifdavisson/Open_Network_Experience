  NOC technicians and district IT staff cannot view sensor and student Chromebook geographical locations on the GIS Campus Map. Technicians responding to localized campus outages lose physical geospatial context and cannot locate which building or classroom has an offline probe.

## SUMMARY
When navigating to the GIS Campus Map (`#nav-monitor-map`) or switching to Slide 2 on the Wallboard, the page fails to initialize the Leaflet map container. A fatal JavaScript `ReferenceError: mapInstance is not defined` (and `ReferenceError: wallboardMapInstance is not defined`) is thrown in `sensors.js:520:5`, halting execution. The backend API is fully functional (200 OK), but the frontend module architecture leaves Leaflet global state variables unshared across ES module boundaries.

---

## REPRODUCTION STEPS
1. Open http://10.98.2.125:8000/ in a modern browser.
2. Observe console logs or navigate to **GIS Campus Map** in the left sidebar navigation (`#nav-monitor-map`).
3. Wait for the view transition.
4. Inspect DevTools Console — observe uncaught runtime exception `ReferenceError: mapInstance is not defined` at `sensors.js:520`.
5. Observe that `#leaflet-map` has 0 child nodes and does not render tiles or sensor pins.

## EXPECTED RESULT
The `#leaflet-map` container should instantiate a Leaflet GIS map with Carto voyager tiles centered on district coordinates (`[35.37452, -119.01874]`), render glowing sensor status markers for all sensors with coordinates, and display a list of active campus coordinates in `#map-sensor-list`.

## ACTUAL RESULT
The Leaflet map never mounts (`leafletContainerFound: false`, `leafletMapChildren: 0`). The container remains a completely blank `div`. The `#map-sensor-list` displays `"No GPS coordinates recorded yet."` without an interactive call-to-action to assign GPS coordinates to fleet sensors.

## ROOT CAUSE HYPOTHESIS
- **Hypothesis:** JavaScript runtime error preventing render due to ES module variable isolation.
- **Confidence:** High (100% deterministic reproduction and stack trace).

**Supporting Evidence:**
- In `main.js` (lines 100-103), `let mapInstance = null;` and `let wallboardMapInstance = null;` are declared with `let`.
- In ES module script tags (`<script type="module">`), top-level `let` variables belong strictly to that module's module record; they are **never** attached to the `window` global object and are **not** exported to other modules.
- In `sensors.js` (lines 520 & 562), `initOrUpdateMap()` and `initOrUpdateWallboardMap()` check `if (!mapInstance)` and `if (!wallboardMapInstance)` without declaring or importing them, triggering an immediate fatal `ReferenceError`.

**Contradicting Evidence:**
- None.

**To confirm root cause, check:**
- Declaring `let mapInstance = null;` and `let wallboardMapInstance = null;` inside `sensors.js` module scope resolves the error and mounts Leaflet immediately.

## RECOMMENDED FIX

### Immediate Fix (unblocks users now)
In `server/static/js/modules/sensors.js`, declare the map instances and caches at the module level:
```javascript
// At top of sensors.js:
let mapInstance = null;
let wallboardMapInstance = null;
let mapMarkers = [];
let wallboardMapMarkers = [];
let SENSORS_CACHE = [];
let CHROMEBOOKS_CACHE = [];
```
In `renderDashboard(sensors, probes, liveStats, chromebooks, roamingTrail)`:
```javascript
SENSORS_CACHE = sensors || [];
CHROMEBOOKS_CACHE = chromebooks || [];
```

### Permanent Fix (addresses root cause & UX)
1. **Module Scoping:** Maintain map state in `sensors.js` where the map rendering logic lives, or export setter functions (`setMapInstance`, `getMapInstance`) if shared across modules.
2. **Empty State Call-to-Action:** When `mapList.length === 0`, render an interactive onboarding prompt in `#map-sensor-list`:
   ```html
   <div style="padding: 16px; text-align: center; border: 1px dashed var(--border); border-radius: 8px;">
       <p style="color: var(--text-muted); font-size: 13px; margin-bottom: 8px;">No GPS coordinates recorded for fleet sensors yet.</p>
       <button class="btn btn-primary btn-sm" onclick="switchView('manage-locations')">📍 Configure Campus & Room Coordinates</button>
   </div>
   ```

### Code Location Hint
