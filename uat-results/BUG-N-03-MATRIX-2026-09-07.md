PRIORITY: 🔴 HIGH

USER IMPACT:
District IT network engineers and NOC technicians relying on On-Demand Live Diagnostics experience false negatives and unhandled test probe execution:
1. When selecting "CIPA Compliance Content Filter Probe" (`cipa`) or "DHCP DORA 4-Way Lease Timing" (`dhcp`), the backend lacks dedicated routing branches, silently falling through to the full 7-Layer OSI suite (`all`) which triggers an unrelated HTTP probe.
2. The default SaaS HTTP probe against `https://google.com` fails across all sensors with `Unreachable` inside the CMP server container because Docker embedded DNS (`127.0.0.11`) enforces a CNAME rewrite to `forcesafesearch.google.com`, which fails glibc standard getaddrinfo lookups (`gaierror -5 No address associated with hostname`).
3. When running the Canvas LMS probe (`canvas`), a CloudFront upstream maintenance response (`HTTP 503 Free-for-Teacher Platform Restoration`) is reported as an absolute network failure (`RED FAIL`) rather than distinguishing upstream application maintenance from network reachability.

---

## SUMMARY
A comprehensive multi-sensor automated execution matrix was conducted across all 3 registered edge sensors (`chromebook-dev-e7573882-80d0-4bec-ab68-4e1f98afd22f`, `f10325921e2b43b2b5fcf33cadad864b`, and `0320589c63904502bd820cb0c321a1b2`) evaluating all 16 on-demand diagnostic test types (totaling 48 automated test executions). While 36 tests passed with SLA compliance (including iPerf3 bandwidth, CAASPP state testing readiness, DNS benchmarks, security gateway latency, Google Classroom, i-Ready, RingCentral VoIP, Zoom STUN jitter, client isolation, east-west VLAN isolation, Wi-Fi RF flapping, and PCAP triggers), 12 tests failed identically across all sensors. Investigation exposed three distinct root causes: a missing backend route dispatch in `sensor_diagnostics.py` for CIPA and DHCP test options, a container DNS resolution failure under Google safe-search CNAME redirection, and binary pass/fail handling for upstream 503 maintenance statuses.

## EXPECTED RESULT
1. When selecting `cipa`, the system should execute the dedicated CIPA filter compliance check (checking `iwf.testfiltering.com`, `ctiru.testfiltering.com`, `testfiltering.pornhub.com`, etc. via `sensor/cipa_compliance.py` or CMP container emulation).
2. When selecting `dhcp`, the system should execute DHCP DORA lease timing inspection (evaluating DORA 4-way handshake duration or interface lease state via `sensor/wifi_dhcp_exporter.py`).
3. When executing `all` or default SaaS HTTP probes, hostname resolution for `google.com` should succeed, falling back to direct public resolvers (`1.1.1.1` or `8.8.8.8`) or handling safe-search CNAME targets gracefully without crashing into `Unreachable`.
4. Upstream maintenance states (`HTTP 503`) with successful TCP/TLS handshakes should be classified as `⚠️ WARNING (Upstream Maintenance)` rather than `🔴 FAIL`.

---

## ACTUAL RESULT
1. `cipa` and `dhcp` have no matching handler in `sensor_diagnostics.py`, falling through to the generic fallback.
2. In the generic fallback, `_live_probe_http("https://google.com")` throws `socket.gaierror: [Errno -5] No address associated with hostname` inside Docker because Docker DNS rewrites `google.com` to `forcesafesearch.google.com` as a CNAME without returning immediate A records.
3. Canvas LMS returns `HTTP 503` from CloudFront and is marked as a network failure.
4. UI displays `🔴 FAIL` for 12 out of 48 test permutations.

## ROOT CAUSE HYPOTHESIS
1. **Missing Route Dispatch (`sensor_diagnostics.py`)**:
   `server/routers/sensor_diagnostics.py` lines 186-651 defines `if tt in ("speedtest", ...):`, `elif tt in ("wifi_flapping", ...):`, etc., but has no branch for `tt in ("cipa", "content_filter")` or `tt in ("dhcp", "lease")`.
2. **Container DNS Resolution Failure (`cmp-server`)**:
   Docker Engine embedded DNS (`127.0.0.11`) responds with a CNAME `forcesafesearch.google.com` when querying `google.com`. In Debian/glibc inside the container, `urllib.request.urlopen("https://google.com")` does not resolve the redirected CNAME target unless ndots or recursive A records are returned.
3. **HTTP 503 Classification**:
   In `sensor_diagnostics.py` line 289, `c_res["status_code"].startswith("2")` treats `503` as a failure even when the network path and SSL handshake are intact.
